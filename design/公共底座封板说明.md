# 公共底座封板说明

## 当前版本

```text
public-foundation.v11
```

当前公共底座已经把真实世界身份、展示投影、账号身份、规则执行、资产事务、结构化战报和通信协议
拆成独立边界。`world_id` 标识真实玩法世界，`skin_id` 只负责展示；角色创世、位置、跃迁、探险、
人物交互和跨世界按钮校验都通过统一世界目录完成。

版本历史由 Git 保存，本文件只描述当前有效契约，不继续维护逐版本建设日志。

## 封板范围

- `message/`：跨驱动消息语义、富文本结构、动作协议和渲染器。
- `launch/`：应用生命周期、模块加载、通信驱动器、命令上下文和显式回复目标。
- `game/core/`：账号、规则、战斗、资产、经济、奖励、行动、周期、内容和持久化底座。
- `game/content/`：稳定名录、官方世界、展示投影、内容扩展和统一装配。
- `game/rules/`：跨组件复用且不读取数据库的具体游戏规则。
- `game/features/`：正式业务用例、联合事务和状态所有权。
- `game/app.py`：数据库、内容、规则与业务服务的唯一装配根。
- `game/cmd/`：命令与 HTTP 接口，只负责接入、调用和展示。
- `.ops/` 与 `.test/`：部署外的审计、脚手架和自动化验收工具。

## 依赖方向

```text
game/cmd        -> game/features + game/app + message + launch
game/features   -> game/rules + game/content + game/core
game/rules      -> game/content + game/core
game/content    -> game.core.gameplay
game/app.py     -> game/features + game/rules + game.content + persistence
launch          -> message
message         -> Python 标准库
```

`launch` 和 `message` 不得导入 `game`。`game.core` 不得导入命令、消息协议、通信驱动器或测试工具。
协议测试不得依赖游戏业务代码。

## 扩展规则

1. 新物品、能力、效果、角色、装备、武器、敌人、伙伴和世界优先通过定义、注册表与内容包扩展。
2. 新玩法调用公共事务和规则能力，不直接写核心聚合或数据库表。
3. 只有公共契约无法表达新能力时才修改核心，并同时升级门禁与回归测试。
4. 破坏存储格式、稳定 ID 或事件语义时必须显式升级版本，不增加兼容空壳掩盖变化。
5. 内容包必须在装配阶段完成依赖拓扑、隐藏引用、估值和内容指纹校验。
6. 世界展示不得承担玩法判断，真实世界不得复制公共规则与资产定义。
7. 战报展示注册表只解释结构化事件，不根据武器名称或具体世界硬编码战斗结论。

## 不在封板范围

- 具体数值平衡、活动排期、玩家文案和网页视觉设计。
- 部署平台、反向代理、证书签发和外部监控系统。
- 人工数据库迁移与外部数据导入。

## 验证

公共底座变更必须通过全量测试、架构门禁、静态检查、编译、扩展审计和真实应用生命周期测试。
完整命令见 [核心封板基线](核心封板基线.md)。
