# 玩家活动协作端口

`player_activity` 不拥有新状态，也不写数据库。它在调用方已经开启的工作单元中统一读取通用行动和持续
探险快照，再通过纯规则投影出玩家唯一活动事实。

正式业务只能注入 `PlayerActivityFeature` 后调用：

- `load_in_uow()`：角色总览等读模型需要完整活动、待领取行动和一致性信息时使用。
- `block_in_uow()`：移动、跃迁、休息、探险、伙伴追踪、灾厄和组队挑战只需判断是否被占用时使用。

阻塞结果必须携带 `PlayerActivityBlock`。其中 `status` 保留业务兼容语义，探险和自动休整都映射为
`exploring`；`kind` 保留精确展示语义，命令层据此显示“探险中”或“自动休整中”。任何组件都不得再次
直接组合 `ActionState` 与 `ExplorationState`。

这个端口是共享只读协作能力，不是全局业务协调器。探险启停、休息恢复、世界移动和战斗结算仍由各自
feature 持有写入口与事务边界。
