# 正式游戏命令层

`game/cmd/` 只负责把消息命令连接到正式游戏业务，不承载规则、数据库实现或平台私有协议。

## 注册命令

```python
from launch.adapter import Depends

from ..command import GameCommand, HelpSpec
from ..dependencies import current_character
from . import service


@GameCommand.handler(
    cmd=("背包", "行囊"),
    help=HelpSpec(
        category="资产",
        summary="查看占用背包空间的战利品和经济物资",
        usage=("背包", "背包 页码"),
    ),
)
async def show_inventory(character=Depends(current_character)) -> None:
    await service.show_inventory(character)
```

- `priority=100` 和 `block=True` 已由 `GameCommand` 提供默认值。
- 命令默认使用 `access="player"`，要求当前身份已经创建角色。
- 创建角色等确实允许未建档身份执行的入口必须显式写 `access="public"`。
- 多个别名写在同一个 `cmd` 元组中，不能复制多个处理函数。
- 需要从全局通栏进入的命令通过 `intent_ids=(...)` 与稳定回复意图绑定；没有正式命令就不能注册通栏链接。

## 帮助登记

公开命令必须在同一个 `GameCommand.handler()` 中提供 `HelpSpec`。帮助注册表会随着二级组件导入自动收集，
`帮助`、`帮助 分类` 和 `帮助 命令` 均由注册结果生成，不允许组件再维护第二份命令清单。

固定分类只有：`角色`、`行动`、`资产`、`世界`、`战斗与社交`、`活动`。一句话用途、命令写法和操作
影响必须使用玩家可见文字，不能暴露内部 ID、数据库字段或 Python 路径。按钮回调、全局通栏内部入口和
测试命令必须显式写 `hidden=True`；命令既不能同时公开和隐藏，也不能省略这项决策。

## 公共依赖

- `current_identity_evidence`：只转换当前消息身份。
- `current_character`：只解析当前账号和角色，不读取其他领域。
- `current_character_overview`：按需读取角色、背包、装配、账本、世界和行动快照。

依赖结果在单条消息的依赖链中自动缓存。普通命令应优先使用最轻量的依赖，不能为了方便统一读取
`current_character_overview`。

`CurrentCharacterResult` 同时携带角色当前 `CharacterDimensionState`。业务正文通过
`current_game_services().world_view(current.dimension)` 取得角色级世界视图；角色详情页直接使用
`overview.dimension`。组件不得读取全局默认 `services.content.projector` 生成玩家可见名称。

## 访问守卫

`access_guard.py` 在业务回调执行前检查 `GameCommand` 的访问元数据。未建档用户访问默认玩家命令时，
只由守卫返回一次创建角色入口，组件回调不会执行；公开命令不受影响。后续战斗、休息或活动状态守卫由对应系统独立注册，不能
全部堆进角色守卫。

## 发送回复

业务只构造 `message.Message`，再调用：

```python
await send_game_reply(reply)
```

`send_game_reply()` 是正式游戏的统一回复流水线。对于已建档玩家的 `DocumentMessage`，它会只读加载
最新人物设置、全服活动热点、有效未读通知数量和待领取行动数量，再由 `GameReplyComposer` 统一生成：

```text
人物头
活动通栏（没有热点时省略）
提醒通栏（没有待办时省略）
组件业务正文
附加区
按钮
```

组件不能调用 `inline_section()` 占用全局通栏，也不能手写彩色 Header。组件提供的普通 Header 只用于
未建档或身份异常等公共回复；已建档玩家的 Header 会统一替换为“境界短名 + 名称 + 等级”。活动通栏
最多显示两个可点击短名，其余热点显示为 `+N`；提醒通栏只显示个人数量。两者都是只读操作，不会自动
参与活动、已读通知、领取奖励或推进行动。

`world_events` 与 `world_events 活动实例ID` 是活动通栏使用的内部入口，不放入公开帮助。具体活动
通过 `game.rules.activity.register_global_activity()` 和稳定 `entry_intent_id` 接入，不能修改回复装饰器。
普通活动名称可以由当前世界皮肤投影；跨界灾厄使用注册时提供的固定展示，命令组件不得按角色当前世界
改写灾厄名称、故事或铭刻之羽文案。

旧版铭刻确认入口和通知已读使用内部英文入口。它们不进入公开命令列表，仍必须经过默认玩家守卫，并由
应用服务重新校验当前角色对目标资产或通知的所有权。兼容按钮只是命令传输，不是权限依据。

图片消息不强行拼接文本外框。最终发送仍由公共驱动器管理器完成，游戏回复层不处理 QQ 私有 payload。

## 横向交互规则

架构封板后，正式命令统一按以下规则组织玩家回复：

- 分页：所有分页列表以 `50` 个条目为每页硬上限，统一校验正整数页码，显示“当前页/总页数 + 总数”，导航顺序固定为“上一页、下一页、返回”。筛选条件必须保留在翻页命令中。
- 确认：只有归航回收保留“报价 -> 确认”的二段流程；其他明确命令直接执行，业务服务仍须在实际写入前重新校验报价、版本和权限。回收确认按钮在前，重新选择或返回在后。
- 失败恢复：可预期失败要说明原因并给出可执行的返回、重新选择或恢复入口；未知异常由 `send_command_failure()` 记录。对仅提示“稍后重试/稍后再试”且没有其他动作的回复，统一回复流水线会为原命令补一次“重试”入口。
- 状态阻塞：命令组件不得根据 `exploring` 等字符串自行编写文案。活动阻塞统一消费业务返回的 `PlayerActivityBlock`，由 `activity_block_feedback()` 区分探险与自动休整；真实战斗的血气归零统一由 `health_depleted_feedback()` 提供休息和纳戒入口。
- 按钮顺序：真正推进当前流程的主操作在前，辅助查询、翻页、返回和危险入口在后。`send_game_reply()` 会保序地先放 `primary`，再放 `secondary`。
- 信息密度：正文优先回答“发生了什么、为什么、下一步是什么”。列表条目、分类和模式选择优先使用 `M.command()` 内联命令，键盘按钮只保留提交、回收确认和少量辅助入口。

`game.cmd.interaction` 是上述规则的共享实现。地图和探险的当前世界完整地点列表是已确认的产品例外：它们保留一次完整展示，但地点名本身必须可直接触发命令，不再为每个地点生成键盘按钮。

## 边界

- `__init__.py` 只放装饰器、命令参数和一次 service 调用。
- 文本解析使用小型纯函数，解析结果再交给 service。
- 只有归航回收由所属业务实现一次性报价凭证；其他命令直接执行，命令层不保存临时业务状态。
- service 通过应用服务操作数据库，组件不能直接修改快照。
