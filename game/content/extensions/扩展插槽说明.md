# 内容与世界扩展插槽

`extensions/` 是正式内容唯一的受控发现边界。发现器只扫描以下两类目录：

```text
extensions/official_content/<name>/extension.py  -> CONTENT_EXTENSION
extensions/official/<name>/extension.py          -> WORLD_EXTENSION
```

扩展模块只能声明冻结数据，不能在导入时修改全局注册表、连接数据库、启动任务或读取玩家状态。发现结果按
稳定 ID 和世界 `order` 排序；文件系统枚举顺序不会改变内容指纹。

可先创建不会参与发现的草稿：

```powershell
python .ops\__main__.py scaffold-extension --kind world --name fourth_world
python .ops\__main__.py scaffold-extension --kind content --name new_armaments
```

脚手架生成带 `_` 前缀的目录，发现器会跳过；补齐描述、展示和契约测试后，去掉目录前缀即可启用。
脚手架拒绝非 ASCII 模块名、Python 关键字和覆盖已有目录。

## 新增共享内容

新增一个目录并导出 `ContentExtension`。其中每个 `ContentPackage` 必须拥有唯一包 ID、版本和显式依赖。
跨世界共享的展示 ID 放在 `display_content_ids`；只属于某个世界皮肤的展示 ID 放在
`skin_display_content_ids`。扩展通过 `skin_overlays` 为已有皮肤提交增量文案，通过
`enemy_behavior_weights` 提交新行为的默认及世界倾向，通过 `market_item_policies` 提交新增可交易物品政策。
新增武器机制仍须同时登记执行、价值、战报展示和测试，扩展槽不会绕过领域契约。

## 新增世界

一个 `WorldExtension` 必须一次性提供：

1. `world_id`、独立空间、地图锚点和地点绑定。
2. 完整皮肤、装备展示样式和敌人展示样式。
3. 宠物物种、秘境、人物伙伴和地点绑定。
4. 敌人行为权重、独占组队首领、来源及逐首领战利品绑定。
5. 独占灾厄定义及对应战斗敌人。
6. 五阶段世界志。
7. 可选的世界自有 `ContentExtension`。

世界扩展加入后，正式装配自动派生可进入世界、皮肤、伙伴、组队首领、敌人倾向、灾厄、世界志和组队
首领遭遇池与奖励映射。旧世界文件、`game/app.py`、命令组件和中央编号表都不需要修改。

## 启动门禁

启动会拒绝以下扩展：重复稳定 ID 或包 ID、世界与空间或皮肤不一致、跨世界伙伴混入、秘境未覆盖宠物、
组队首领来源漏项、灾厄与战斗敌人不一一对应、世界志来源错误、专属皮肤缺少自身空间或首领展示、未知
内容引用和未声明的运行依赖。

`.test/world_extension_contract_test.py` 构造一个完整第四世界，并验证战利品、经济审计、组队奖励解析及
打乱扩展输入顺序后的内容指纹。`.test/content_extension_contract_test.py` 验证共享内容可以自行增加规则、
三世界展示、行为倾向和市场政策。`.test/extension_scaffold_test.py` 验证草稿隔离、命名和防覆盖。
这三项是扩展插槽的永久门禁。
