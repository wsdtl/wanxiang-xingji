# 本地维护工具

`.ops/` 只放正常运行不需要的本地维护和内容激活工具，游戏运行期不会从这里导入任何模块。
最小运行镜像可以排除该目录，但发布流程必须从维护工作区或维护镜像访问同一主数据库卷后执行内容激活。

当前入口：

```powershell
python .ops\__main__.py content-status --database game\database\wanxiang_xingji.db
python .ops\__main__.py content-activate --database game\database\wanxiang_xingji.db --fingerprint <当前内容指纹>
python .ops\__main__.py scaffold-extension --kind world --name fourth_world
python .ops\__main__.py scaffold-extension --kind content --name new_armaments
python .ops\__main__.py audit-extension --all
```

发布新增世界包或通用内容包时，先对明确的数据库执行 `content-status`，核对输出中的绝对
`database_path` 并复制 `current_fingerprint`，再将同一路径和完整指纹传给 `content-activate`。
`content-status` 省略 `--database` 时才会使用项目 `.env`，`content-activate` 不允许省略目标数据库。
激活目标文件名还必须是 `wanxiang_xingji.db`；审计副本应放入独立目录并保留这个规范文件名。
激活命令会执行以下保护：

- 传入指纹必须等于当前代码实际装配出的指纹。
- 内容发生变化但包版本未提升时拒绝发布。
- 切换前只读扫描有效伙伴秘境和未结算跨界灾厄；任一会话仍依赖旧内容时拒绝激活并输出阻塞类型与
  会话标识，不自动删除玩家资产或排行。待挑战组队首领会在切换后失效，由队长重新选择，不阻塞发布。
- 真正写入前自动在线备份主数据库，并沿用最多三份的备份轮换规则。
- 使用旧 revision 和旧指纹执行 CAS；并发发布不能互相覆盖。
- 已经激活的同一内容重复执行时直接成功，不重复备份或提升 revision。

标准顺序：

```powershell
python .ops\__main__.py audit-extension --all
python .ops\__main__.py content-status --database game\database\wanxiang_xingji.db
python .ops\__main__.py content-activate --database game\database\wanxiang_xingji.db --fingerprint <current_fingerprint>
python .ops\__main__.py content-status --database game\database\wanxiang_xingji.db
```

Docker/Linux 部署从项目根目录通过 `start.sh` 复用正式虚拟环境和配置文件：

```sh
bash start.sh python .ops/__main__.py audit-extension --all
bash start.sh python .ops/__main__.py content-status --database game/database/wanxiang_xingji.db
bash start.sh python .ops/__main__.py content-activate --database game/database/wanxiang_xingji.db --fingerprint <current_fingerprint>
bash start.sh python .ops/__main__.py content-status --database game/database/wanxiang_xingji.db
```

扩展脚手架只接受以小写字母开头的 ASCII Python 模块名，并拒绝覆盖已有目录。它会在正式
发现目录下创建带 `_` 前缀的草稿，例如 `_fourth_world`；发现器明确跳过该目录，因此未完成
内容不会影响启动。实现 `WORLD_EXTENSION` 或 `CONTENT_EXTENSION`、完成契约测试后，去掉
目录名前导下划线即可进入确定性自动发现，不需要修改中央世界表、`game/app.py` 或命令组件。
